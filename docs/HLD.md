# HLD: доказательность прежде автоматической вёрстки

## Компоненты и поток

1. Реестр источников `data/evidence.json:sources` — URL, редакция, доступ, дата,
   права и SHA-256 разрешённого файла. Старые кандидаты — внешние leads.
2. Реестр юрисдикций `data/jurisdictions.json` — много записей на территорию,
   семьи, административные связи и отдельно датированные позиции общения/признания.
3. Сборщик источников — ручной разрешённый поиск/просмотр; автоматической
   загрузки в первой версии раннера нет. DNS/HTTP/TLS ошибки раздельны.
4. Дедупликатор — совпавший SHA-256 плюс проверенные edition/work/language;
   одинаковые имена без редакции не доказывают дубликат.
5. Нормализатор утверждений — ID, формулировка, категория, контекст, цитата,
   перевод, применимость и ссылки. Не толкует церковные тексты сам.
6. Доказательная матрица — `claims`, отдельно подтверждение, опровержение,
   неизвестность и конфликт; никогда не заменяет неизвестное нулём.
7. Вычислитель пересечения — только при закрытом проверенном реестре,
   полном контексте и подтверждении всех нужных юрисдикций нужной семьи.
   Исключения, конфликт или локальный обычай блокируют абсолютное утверждение.
8. Редакторские проверки — источники, религиовед, языки, литература, дизайн,
   типографика, доступность. ИИ-роль не внешняя церковная/носительская экспертиза.
9. Сохранённый генератор — пять прежних Markdown + sources.json → пять
   исторических DOCX-макетов (universal: три колонки, прочие: одна).
   Новая матрица books/editions.json: пять корпусов → девять языковых целей,
   сегменты books/<id>/segments.json. Universal EL/EN/BG с аппаратом RU;
   страновые молитвенные блоки HY/RU, HY/EN, BG/RU, BG/EN, EL/RU, EL/EN,
   CU/RU, CU/EN с аппаратом RU либо EN. Девять содержательных сборок пока
   заблокированы, генератор готовых языковых изданий не заявляется.
   Инициаль только по явному маркеру prayer; текст графемы не нормализуется.
10. Валидатор — схемы, ссылки, права, счётчики, ZIP/XML, текст, таблицы,
    шрифт по фактическим codepoints, SHA-256. XML не заменяет рендеринг.
11. Журнал — root progress.md, `data/pipeline/state.json`,
    структурированные события `data/pipeline/progress.json`, отчёт.

`источник → проверка человеком/редактором → evidence → intersection →
manuscript/sources → DOCX → проверка → явная публикация`.
Генератор не превращает search_only в confirmed.

## Границы доверия

Внешний текст — данные, никогда команды или инструкции установки.
Нет eval, shell=True, загрузки по произвольной команде, hooks/submodules/LFS.
Локальные пути манифеста ограничены проектными books/deliverables; traversal
и symlink наружу отвергаются. Только HTTPS-источники для будущего получения;
HTTP lead не разрешение на загрузку.
Конкретные молитвы требуют проверенной редакции, права, атрибуции и provenance.
Публичный доступ ≠ открытая лицензия. Нет чужих полнотекстовых импортов.

## Раннер и ошибки

Ручной CLI, dry-run по умолчанию, без сетевых запросов/записей/публикации.
Execute: конечный проход выбранных фаз, monotonic deadline, source budget,
максимум 3 попытки, resume. Одна и та же блокировка не ретраится автоматически:
новая попытка требует явного retry и описания новой гипотезы.
Статусы pending/running/passed/blocked/failed/needs_human, причины и время.
Независимые P5 layout могут выполняться при blocked P2/P3: успешная техническая
сборка макетов не меняет статус содержательной приёмки.
Interrupted running при resume становится failed, не выдаётся за passed.

Публикация через --publish — только явный запрос, проверенная собственная ветка,
allowlist проектных файлов; в этой среде commit/push делается инструментом PR.
Раннер не вызывает git push и не обещает фактическую публикацию.
Нет новых workflows, платных сервисов, бесконечного цикла или новых сессий.

## Приёмка и открытые задачи

Готовый комплект — пять содержательных корпусов в девяти языковых сборках
с доказательствами, правами, редактурой, Markdown и читаемыми DOCX,
не пять прежних макетов или девять запланированных файлов.
Универсальная полнота требует закрытого проверенного охвата и явно описанного
контекста; отсутствие источника не ложность и не разрешение.
Визуальная приёмка needs_human до реального просмотра. Церковная интерпретация
не поручается числовому рейтингу. Сетевая проверка и импорт — пока ручные,
не испытанная автоматизация сбора не заявляется.

## Языковые ворота и исследованные аналоги

`scripts/book_editions.py` отдельно проверяет точные девять ID, языковые
поля и безопасные пути. В сегменте: группа, глава, роль, язык, точный источник
и участок, редакция, разновидность, произношение, ссылка на оригинал,
переводчик и происхождение перевода. Подтверждённый молитвенный текст требует
проверенных прав, SHA и языка своего источника; перевод проверяется независимо.
Современный армянский требует первично проверенного свидетельства применимости
к Армении. CU и RU не взаимозаменяемы; транслитерация не заполняет слот перевода.
Одинаковый group_id — техническое соответствие, не автоматическая экспертиза
смысловой эквивалентности: даже заполненный корпус получает needs_human.
Доказательные ворота универсального ядра не отменены языковой полнотой.

Разные редакции/армянские разновидности одной группы могут сосуществовать.
`editions[].segment_selection` задаёт слот `group:kind:language` → точный
segment_id, historical_edition, language_variety и pronunciation. Без явного
выбора слот не заполнен; иной вариант или перевод не выбранного оригинала
не засчитывается. Общие edition-level null не заменяют конкретную редакцию.
Подтверждённые внешние пояснения/транслитерации проходят те же проверки
источника и независимых прав. Собственный аппарат отдельно отмечается
origin=author_created, attribution и rights=project_original; молитвенный
текст так освобождать от источниковых/правовых проверок нельзя.

Отчёт data/pipeline/editions.json считает цели, существующие целевые файлы
и принятые издания раздельно; доля переводов отдельно от общей полноты сегментов.
Null при отсутствии отдельных слотов перевода не заменяется нулём.
Файлы-пробы deliverables/proofs/ не издания и не молитвы; редактируемый
источник data/research/layout-proofs.json, сборка scripts/build_mvp_proofs.py.
Поддержка двух/трёх равных колонок не доказывает реальную пагинацию без рендерера.

Аналоги и границы чтения — research/book-analogues.md; реестр 36 supplied
observed и 63 proposed — data/research/mvp-features-99.json. P1 проверяет
реестр, не реализацию всех 99 пунктов. Авторское оглавление — book-decisions.md,
MVP главы 1,2,5,8,9,10,12. Ни полный суточный круг, ни нотация, ни весь текст
литургии не обязательны для MVP. Бадарак не подменяется византийской службой.
