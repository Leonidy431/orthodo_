# Фазы и критерии приёмки

| Фаза | Входы | Выходы | Приёмка | Блокировка |
| --- | --- | --- | --- | --- |
| P0 | История PR, утверждённый commit, доступные инструменты | Аудит, диагностика, повторное использование | Спецификация прочитана, инструменты/сеть различены | Нет исходной спецификации |
| P1 | P0, последний комментарий, ограниченно исследованные аналоги | scope, пять корпусов, девять языковых целей, HLD, оглавления, матрица, 99 особенностей | Точные языки, 36 supplied observed / 63 proposed; проверка реестра не реализация всех 99 | Противоречивый охват/языковая матрица требует решения |
| P2 | Реестр источников, четыре страны | Небольшая первично проверенная выборка правил/текстов | По каждой стране хотя бы одно применимое подтверждение с цитатой/разделом и правами для воспроизводимого текста | DNS/доступ, неизвестные права; блокировка не ведёт к выдумкам |
| P3 | P2, открытый реестр юрисдикций | Расширенный проверенный реестр, универсальное ядро и исключения | Охват закрыт первичными свидетельствами; всеобщность проверена; исходные три отдельно | Неполный реестр, конфликт, неизвестность |
| P4 | P2/P3, принятые утверждения и языковые сегменты | Пять корпусов с главами MVP 1,2,5,8,9,10,12 | Все обязательные оригиналы/переводы по группам и соответствующая аппарату RU/EN версия; права/редакция независимо | Нет содержания/перевода/прав; транслитерация не замена |
| P5 | Честно маркированные рукописи, матрица целей | Дизайн, девять целевых DOCX после допуска; две пробы отдельно | Равные колонки, повтор шапки, Unicode/графемы/пагинация; прежние пять макетов не девять изданий | Девять целей пока не генерируются; визуальный просмотр needs_human, не XML |
| P6 | Все фазы и проверки | Финальный отчёт, журнал, commit/push | Все содержательные и визуальные критерии выполнены, remote SHA подтверждён | Нельзя объявить комплект готовым при blocked P2/P3/P4 |

P5 разрешён независимо как дизайн-макет. Это не обход P2/P3/P4 и не итоговая
готовность. Сборщик и раннер явно сохраняют этот смысл в состоянии.

Проектные ограничения ручного запуска: 20 минут, до 100 новых источников,
до 3 попыток шага. Это не квоты GitHub. Автоматической сети в v1 раннера нет:
network_requests = 0. Источник считается новым лишь при явном добавлении в реестр,
а не при каждом resume. При достижении лимита сохраняется blocked с причиной.
Проверки без изменения входов не ретраятся; --retry-reason задаёт новую гипотезу.

Сначала публикуется P1 как спецификация, затем выполняются доступные независимые
этапы. Заблокированный содержательный этап не прячется за общей зелёной галочкой.

## Ручной CLI

Из любой рабочей папки, без установки пакетов:

```sh
python -B /home/runner/work/orthodo_/orthodo_/scripts/run_book_pipeline.py --dry-run
python -B /home/runner/work/orthodo_/orthodo_/scripts/run_book_pipeline.py --execute --max-seconds 1200 --max-sources 100
python -B /home/runner/work/orthodo_/orthodo_/scripts/run_book_pipeline.py --execute --resume --phase P5 --retry-reason "проверена новая редакция исходника"
python -B /home/runner/work/orthodo_/orthodo_/scripts/run_book_pipeline.py --execute --resume --phase P1 --publish
python -B -m unittest discover -s /home/runner/work/orthodo_/orthodo_/tests -p 'test_book_pipeline.py' -v
```

Первый execute используется только при отсутствии state.json; далее обязателен
resume, чтобы не сбрасывать историю попыток. Без изменения входов blocked/failed/
needs_human не повторяются без новой явной гипотезы. Лимит попыток сохраняется.
После изменения входов старые passed инвалидируются. Каждая фаза исполняется
не более одного раза за вызов; автоматического повтора DNS нет.
Exit 0: запрошенные фазы passed либо dry-run; exit 2: есть blocked/failed/needs_human.
Неверные параметры вызывают ошибку, а не обход ограничений.

`--publish` работает только вместе с execute, проверяет точное имя ветки
`copilot/third-attempt-book-research` и allowlist корневых файлов/папок проекта.
Он сохраняет запрос `publication.status=needs_human`; сам не делает commit/push.
Фактический секрет-скан и публикацию в этой среде выполняет инструмент PR.
Публикация и автоматическая готовность не подразумеваются кодом завершения.

Состояние: data/pipeline/state.json; структурированный журнал:
data/pipeline/progress.json. Они не содержат сетевых токенов/куки.
Раннер v1 не собирает внешние данные автоматически: лимит источников ограничивает
новые записи относительно предыдущего состояния, сетевых запросов **0**.
Содержательные стадии даже после появления кандидатов сохраняют needs_human:
редакторская приёмка не автоматизирована и не может быть заявлена только раннером.

## Уточнение языкового MVP

Оглавление 12 глав и решения — book-decisions.md. Сначала семь выбранных глав;
прочие расширяются после полезного результата. Все 99 требований не блокируют
первый выпуск. Свидетельства аналогов отдельно от нашей повторной проверки.

```sh
python -B /home/runner/work/orthodo_/orthodo_/scripts/book_editions.py
python -B /home/runner/work/orthodo_/orthodo_/scripts/book_editions.py --write-report
python -B /home/runner/work/orthodo_/orthodo_/scripts/build_mvp_proofs.py
python -B /home/runner/work/orthodo_/orthodo_/scripts/build_mvp_proofs.py --write
python -B /home/runner/work/orthodo_/orthodo_/scripts/build_mvp_proofs.py --check
python -B -m unittest discover -s /home/runner/work/orthodo_/orthodo_/tests -p 'test_book*.py' -v
```

По умолчанию обе новые команды не пишут и не обращаются к сети.
Первый CLI: exit 2 при пропусках, exit 0 при заполненных слотах, но всё ещё
needs_human, не разрешение публикации. Только --write-report сохраняет отчёт.
Второй CLI проверяет структурные пробы на составительских вопросах;
--write явно создаёт два DOCX, --check сравнивает их побайтово с источником.
Пробы не содержат молитв и не засчитываются как целевые издания.

P1/P4/P5 теперь читают языковую матрицу. Fingerprint включает editions.json,
segments.json, исследовательские JSON и архитектурные документы: старый passed
не подтверждает изменённую спецификацию. История конечного раннера сохранена,
лимит попыток не сброшен; новый read-only отчёт не объявляется успешным P2/P4.
